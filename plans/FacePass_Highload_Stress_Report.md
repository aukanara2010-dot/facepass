### 4.2 BottleNecks — Что сломается первым

```
Приоритет отказа:
1. CPU (нейронная сеть buffalo_l)  ← ПЕРВЫЙ
2. Network (S3 upload/download)    ← ВТОРОЙ  
3. Disk (IOPS PostgreSQL)          ← ТРЕТИЙ
```

**Обоснование:**

**CPU (нейронная сеть) — КРИТИЧЕСКИЙ:**
- avg_runtime достиг 11.04 сек при 44.9% загрузке CPU (7.177 из 16 ядер)
- Модель buffalo_l — CPU-bound, не GPU-accelerated
- При удвоении нагрузки avg_runtime вырастет до ~22 сек, очередь взорвётся
- Текущий запас: **~55% CPU свободно**, но нейронная сеть не масштабируется горизонтально без добавления воркеров

**Disk (PostgreSQL IOPS) — УМЕРЕННЫЙ:**
- disk_read_mbps ≈ 0.0 МБ/сек (почти нет чтения)
- disk_write_mbps ≈ 0.01–0.03 МБ/сек (минимальная запись)

### 4.4 Reliability — Рекомендации по отказоустойчивости

#### Circuit Breakers

**Проблема:** При переполнении очереди Celery (>3000 задач) система продолжает принимать новые задачи, усугубляя ситуацию.

**Решение:**
```python
# В services/tasks.py — добавить проверку перед постановкой задачи
from celery import current_app

def check_queue_health() -> bool:
    inspector = current_app.control.inspect()
    active = inspector.active() or {}
    reserved = inspector.reserved() or {}
    total = sum(len(v) for v in active.values()) + \
            sum(len(v) for v in reserved.values())
    return total < MAX_QUEUE_SIZE  # MAX_QUEUE_SIZE = 3000

# Circuit Breaker: если очередь переполнена — вернуть 503
if not check_queue_health():
    raise HTTPException(status_code=503, detail="Queue overloaded")
```

#### Dead Letter Queues (DLQ)

**Проблема:** Задачи, упавшие с ошибкой (S3 timeout, OOM в нейронной сети), теряются без возможности повторной обработки.

**Решение:**
```python
# В core/celery_app.py
CELERY_TASK_ROUTES = {
    'services.tasks.sync_s3_photos_task': {
        'queue': 'photos',
        'dead_letter_exchange': 'photos.dlq',
        'dead_letter_routing_key': 'photos.failed',
    }
}

# Отдельный воркер для DLQ с алертингом
@app.task(queue='photos.dlq')
def handle_failed_photo(task_id: str, error: str, payload: dict):
    logger.error(f"Task {task_id} failed: {error}")
    # Сохранить в PostgreSQL для ручного ретрая
    # Отправить алерт в Slack/PagerDuty
```

#### S3 Lifecycle Policies

**Проблема:** 4 ТБ за 30 часов → при масштабировании стоимость хранения взрывается.

**Решение (AWS S3 Lifecycle):**
```json
{
  "Rules": [
    {
      "ID": "photos-lifecycle",
      "Status": "Enabled",
      "Transitions": [
        {"Days": 30, "StorageClass": "STANDARD_IA"},
        {"Days": 90, "StorageClass": "GLACIER"},
        {"Days": 365, "StorageClass": "DEEP_ARCHIVE"}

      "NoncurrentVersionExpiration": {"NoncurrentDays": 7}
    }
  ]
}
```

**Экономия:** $94.2/мес → $16/мес для 4 ТБ при переводе в Glacier через 90 дней.
